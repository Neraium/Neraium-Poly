## Review implementation

The sampler adds a correlation ID to its existing loopback request and records only bounded transport-stage times, first decoded body chunk and JSON decode completion. The producer logs that ID with UTC ASGI arrival and elapsed handler dispatch, runtime lock wait, frame construction, handler return, response headers, and final body send. It also records the frame identity, original available-at, ingestion age and fresh-book predicate. This preserves the 3-second read timeout, 4-second existing streamed-read check, 8 MiB body bound and all freshness/identity semantics. No changed report or frame timestamps. Apply the instrumentation to both sides only in a future separately authorized observation. Client-only data will narrow the timeout stage but cannot identify server-side lock or serialization time.

For a future timeout, join the request ID from the sampler's bounded recent reads to the producer log. No server log means arrival/retention remains unknown. A producer handler start late relative to ASGI arrival shows dispatch delay. Late lock acquisition shows producer lock contention. Late frame construction or late response-start after handler return separates producer work from encoding/middleware. Fast server-side send paired with client body idle shifts the investigation to response delivery or client scheduling. A degraded trace with fresh-book false versus excessive ingestion age will disambiguate those predicates. An interrupted server request may lack later stages.

It resumes using that exact anchor, selects the direct feed in quiesced mode and the shared sampler in shadow mode, and checks evidence before returning readiness. It never restarts a unit.
